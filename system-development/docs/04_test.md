## テスト

**テスト**とは、プログラムが**仕様どおりに動くか**を確かめる作業です。
**期待値（こうなるはず）と実際の結果を比べる**のがポイントです。

### テストの種類

| 開発の工程 | | テスト | 確かめること |
| --- | --- | --- | --- |
| 要件定義 | ↔ | 運用（受入れ）テスト | 利用者が業務で使えるか |
| システム要件定義・設計外部設計 | ↔ | システムテスト | システム全体が要件どおりか |
| 内部設計システム要件定義・設計 | ↔ | 結合テスト | モジュール同士をつないで動くか |
| プログラミング | ↔ | 単体テスト | モジュール1つが正しく動くか |

修正後に、今まで動いていた部分がこわれていないか確かめる → **回帰（リグレッション）テスト**

### テストケースの作り方

| 方法 | 見るもの | 技法 |
| --- | --- | --- |
| ブラックボックステスト | 仕様（入力と出力） | **同値分割**：同じ結果になる入力をグループに分け、各グループから代表値を選ぶ<br>**境界値分析**：条件が切り替わる値と、その前後の値をテストする |
| ホワイトボックステスト | プログラムの中身 | **命令網羅**：全部の行を通る<br>**分岐網羅**：if が真・偽の両方<br>**条件網羅**：各条件が真・偽の両方 |

### スタブとドライバ

| 名前 | 何の代わり？ | 使う場面 |
| --- | --- | --- |
| スタブ | 呼ばれる側（下位）の未完成モジュール | トップダウンテスト |
| ドライバ | 呼び出す側（上位）のモジュール | ボトムアップテスト |

### Java の assert

```java
assert Purchase.subtotal(100, 3) == 300 : "100円×3個";
```

- 条件が true → 合格（何も起きない）
- 条件が false → `AssertionError` で止まる
- **`java -ea クラス名`** で実行する（`-ea` がないと assert は無視される）
