5つのテーブル（エンティティ）と属性が書いてあります。テーブル同士のつながり（リレーション）を線で結び、線の両端に多重度を書きましょう。PK は主キー。

問い

  1. 同じ名前の列が別のテーブルにも出てくるところに、線を引こう。線は何本？　 本
  2. 線の両端に、右の多重度（1、0..* など）を書こう。「1」の側と「多」の側は、どうやって見分けた？
  3. students と subjects は、どんな関係？　直接つながっていないのはなぜ？

線の端に書く多重度

1 ちょうど1件 0..1 0件か1件
1..* 1件以上 0..* 0件以上（* でも可）

例：A　1 ────── 0..*　B
A 1件に、B が0件以上つながる。
B 1件から見ると、A はちょうど1件。

ER図ワークシート　解答学生管理システム

解答
線 外部キー（CREATE文） 「1」側 「多」側 「0以上」になる理由（実データ）
teachers ─ classes classes.teacher_id NOT NULL 担任はちょうど1人 0クラス以上 森先生・岡田先生は担任を持たない
teachers ─ subjects subjects.teacher_id NOT NULL 担当はちょうど1人 0科目以上 高橋先生〜山本先生は科目を持たない（森先生は2科目）
classes ─ students students.class_id NOT NULL 所属はちょうど1クラス 0人以上 ITエンジニア学科以外は学生がいない
students ─ scores scores.student_id NOT NULL ちょうど1人 0件以上 坂本さんはビジネスマナー未受験
subjects ─ scores scores.subject_id NOT NULL ちょうど1科目 0件以上 新しく開講した科目は成績がまだない
  • 問い1：5本（外部キーの数＝線の数）。問い2：外部キーを持っている側が「多」、参照される側が「1」。NOT NULL なので「1」側は 1（0..1 ではない）。
  • 問い3：多対多（1人が複数の科目を受け、1科目を複数人が受ける）。多対多は直接つなげないので、中間テーブル scores で「1対多」2本に分ける。

発展：teachers と subjects が多対多のとき学生管理システム

発展

「1つの科目を複数の教員で担当する（例：データベースを森先生と岡田先生の2人で担当）」ことも認めると、teachers と subjects は多対多になります。多対多は直接線で結べないので、中間テーブル teacher_subjects をはさみます（色付きが変更箇所）。

ポイント

  • subjects.teacher_id は1列なので、1科目に教員を1人しか書けない。2人目を入れる列を増やす（teacher_id2…）のは第1正規形違反。
  • そこで subjects から teacher_id を削除し、「どの教員がどの科目を担当するか」の組を1行ずつ teacher_subjects に記録する。
    例：(森, データベース)、(岡田, データベース)、(森, ネットワーク基礎) … の3行。
  • 多対多1本 → 「1対多」2本に分解。線は 5本 → 6本。scores（学生×科目）と同じ形。
  • UNIQUE (teacher_id, subject_id) で同じ組の二重登録を防ぐ。
  • 注意：元の設計では NOT NULL で「科目には必ず担当が1人いる」を保証できたが、中間テーブルでは担当0人の科目も登録できてしまう（subjects 側は 1..* にしたくても、外部キーだけでは強制できず 0..* になる）。
CREATE TABLE subjects (
    subject_id   INTEGER PRIMARY KEY,
    subject_name TEXT NOT NULL UNIQUE,
    credit       INTEGER NOT NULL CHECK (credit > 0),
    teacher_id   INTEGER NOT NULL, ...   -- 削除
);

CREATE TABLE teacher_subjects (         -- 追加
    assignment_id INTEGER PRIMARY KEY,
    teacher_id    INTEGER NOT NULL,
    subject_id    INTEGER NOT NULL,
    FOREIGN KEY (teacher_id) REFERENCES teachers(teacher_id),
    FOREIGN KEY (subject_id) REFERENCES subjects(subject_id),
    UNIQUE (teacher_id, subject_id)
);
