## データベースとは

### 特徴
  
| 特徴          | 説明                                | 具体例                                                                                          |
| ----------- | --------------------------------------- | -------------------------------------------------------------------------------------------- |
| **独立性**     | データベースのデータと、それを利用するプログラムを**別々に管理できる**こと | 学校の「学生名簿」をデータベースに保存しておけば、Webシステムを変更しても、学生名簿そのものはそのまま利用できる。逆に、データの保存方法を変更しても、プログラムを大きく変更せずに済む |
| **一貫性・整合性** | データに矛盾がなく、正しい状態を保てること               | 学生の学籍番号を「1001」と登録したら、別の場所で同じ学生を「1002」として登録しないようにする。また、存在しない学生の成績を登録できないようにする           |
| **同時アクセス**  | 複数の人が同時にデータベースを利用できること              | 学校の成績管理システムで、先生Aが1組の成績を入力している間に、先生Bが2組の成績を入力できる。複数人が同時に利用しても、データが壊れないように管理される                |

### データベースの種類
- RDB
- オブジェクト指向データベース
- キーバリュー型データベース
- 列試行データベース
- ドキュメント試行データベース
- グラフデータベース


| 種類                       | データの持ち方                    | わかりやすいイメージ                          | 代表的なDBMS・製品                                            | 主な用途                          |
| ------------------------ | -------------------------- | ----------------------------------- | ------------------------------------------------------ | ----------------------------- |
| **RDB**<br>リレーショナルデータベース | 表（テーブル）で管理             | Excelのような表を複数作り、表同士を関連付ける        | **MySQL**、PostgreSQL、Oracle Database、SQL Server、SQLite | Webシステム、学校の成績管理、銀行、販売管理など     |
| **オブジェクト指向データベース**       | オブジェクトとして管理            | データと、それを操作する処理をひとまとめにする          | **ObjectDB**、db4o                                      | オブジェクト指向プログラムと組み合わせたシステムなど    |
| **キーバリュー型DB**       | キー（Key）と値（Value）の組み合わせ | 「ユーザーID → ユーザー情報」のように、キーからデータを取得 | **Redis**                         | キャッシュ、セッション管理、高速なデータ取得など      |
| **列指向データベース**     | データを列単位で保存             | 📈「売上金額だけ」など、必要な列をまとめて高速に集計できる    | **Google BigQuery**、Amazon Redshift          | 大量データの分析・集計（OLAP）、データウェアハウスなど  |
| **ドキュメント指向DB**           | JSONなどのドキュメントとして管理     | 📄 1人分の情報を1つのJSONデータとしてまとめる         | **MongoDB**                  | Webアプリ、スマホアプリ、柔軟なデータ構造のシステムなど |
| **グラフデータベース**            | ノードとエッジ（関係）で管理         | 🕸️ 「誰と誰がつながっているか」を中心に管理            | **Neo4j**                               | SNS、推薦システム、経路検索、ネットワーク分析など    |



| データベースの種類          | SQLを使う？           | 代表例                                     | 補足                               |
| ------------------ | ----------------- | --------------------------------------- | -------------------------------- |
| **RDB**            | **○ 使う**          | MySQL、PostgreSQL、Oracle Database、SQLite | SQLが基本的な操作言語                     |
| **オブジェクト指向DB**     | **△ 製品による**       | ObjectDB                                | SQLではなく、Javaなどのオブジェクトを直接扱うものもある  |
| **キーバリュー型DB（KVS）** | **× 基本的に使わない**    | Redis、DynamoDB                          | キーを指定してデータを取得する                  |
| **列指向DB**          | **○ 多くは使う**       | Amazon Redshift、Google BigQuery         | 大量データの分析・集計にSQLを使う               |
| **ドキュメント指向DB**     | **× 基本的にSQLではない** | MongoDB                                 | MongoDB Query Language（MQL）などを使う |
| **グラフDB**          | **△ 製品による**       | Neo4j                                   | Neo4jでは**Cypher**という言語を使う        |

- どういったDBMS(データベース管理システム）を使ったことがあるかは経歴書に記載できる

## SQLite
https://sqlite.org/whentouse.html

SQLiteは「アプリと同じ場所にデータベースを置いて、シンプルに使う」用途に向いている。

### SQLiteが向いているケース
- スマートフォン・ゲーム・家電・IoT機器などの組み込み
- 小～中規模のWebサイト
- CSVなどを使ったデータ分析
- サーバー側で使うアプリ専用のデータベース
- 一時的なデータベース
- テスト・デモ用
- SQLの教育・学習用
