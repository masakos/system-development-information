## Excelの一覧とデータベースの違い

学校の「先生・学生・学科」の情報を、**Excelの一覧で管理する場合**と**データベースで管理する場合**で比べてみます。

---

### 1. Excelの一覧で管理する場合

学生名簿をExcelで1枚のシートにまとめると、例えば次のようになります。

**シート「学生名簿」**

| 学籍番号 | 氏名 | ふりがな | 生年月日 | 入学年度 | 学科 | 担任 |
| --- | --- | --- | --- | --- | --- | --- |
| 261001 | 青木翔 | あおきしょう | 2007/5/12 | 2026 | ITエンジニア学科 | 佐藤太郎 |
| 261002 | 石川葵 | いしかわあおい | 2007/7/23 | 2026 | ITエンジニア学科 | 佐藤太郎 |
| 261003 | 上田陸 | うえだりく | 2008/2/15 | 2026 | IT エンジニア学科 | 佐藤先生 |
| 261004 | 遠藤美月 | えんどうみつき | 2007/9/30 | 2026 | ITエンジニア科 | 佐藤太郎 |
| 261004 | 大塚悠真 | おおつかゆうま | 2007/11/03 | 2026 | ITエンジニア学科 | 佐藤太郎 |
| … | … | … | … | … | … | … |

一見わかりやすい表ですが、よく見ると困ったことが起きています。

### 2. Excelの一覧で困ること

| 困ること | 表の中の例 |
| --- | --- |
| **同じ情報を何度も書いている** | 「ITエンジニア学科」「佐藤太郎」が20人分、20回書かれている |
| **書き方がバラバラになる（表記ゆれ）** | 「IT エンジニア学科」（空白あり）、「ITエンジニア科」、「佐藤先生」が混ざっている。<br>→「ITエンジニア学科の学生」を絞り込むと、この学生が漏れてしまう |
| **修正が大変・直し忘れが起きる** | 担任が別の先生に変わったら、20行すべてを書き換える必要がある。1行でも忘れると、担任が2人いるように見えてしまう |
| **ありえないデータも入ってしまう** | 学籍番号「261004」が2人いる。生年月日の書き方も「2007/9/30」「2007/11/03」とそろっていない |
| **表にいない情報は管理できない** | まだ学生がいない学科（建築学科など）や、担任を持っていない先生は、この表のどこにも出てこない。<br>先生の採用日などを書く場所もない |

### 3. データベースで管理する場合

データベースでは、**「何についての情報か」ごとに表（テーブル）を分けて**、番号（ID）でつなぎます。

```mermaid
erDiagram
    teachers ||--o{ classes  : ""
    classes  ||--o{ students : ""
```

↑ 表と表のつながりを描いたこの図を **ER図** と呼びます（くわしくは次の資料で学びます）。
「先生1人に、クラスが0個以上」「クラス1つに、学生が0人以上」つながっている、という意味です。

**teachers（先生）** … 先生の情報は、先生1人につき1行だけ

| teacher_id | teacher_name | kana | hire_date |
| --- | --- | --- | --- |
| 1 | 佐藤太郎 | さとうみほ | 2012-04-01 |
| 2 | 鈴木健一 | すずきけんいち | 2015-04-01 |
| … | … | … | … |
| 8 | 森隆 | もりたかし | 2020-04-01 |

**classes（クラス）** … 「何年度入学のどの学科か」と、その担任。担任は名前ではなく**先生の番号**で持つ

| class_id | enrollment_year | department_name | teacher_id |
| --- | --- | --- | --- |
| 1 | 2026 | ITエンジニア学科 | 1 |
| 2 | 2026 | ITキャリア養成科 | 2 |
| … | … | … | … |
| 4 | 2026 | 建築学科 | 4 |

**students（学生）** … 学科名や担任名は書かず、**クラスの番号**だけを持つ

| student_id | student_name | kana | birth_date | class_id |
| --- | --- | --- | --- | --- |
| 261001 | 青木翔 | あおきしょう | 2007-05-12 | 1 |
| 261002 | 石川葵 | いしかわあおい | 2007-07-23 | 1 |
| 261003 | 上田陸 | うえだりく | 2008-02-15 | 1 |
| … | … | … | … | … |

- 学生の `class_id` が `1` → classes の1行目を見ると「2026年度 ITエンジニア学科」
- そのクラスの `teacher_id` が `1` → teachers の1行目を見ると「佐藤太郎」

というように、**番号をたどって**情報をつなげます。
このように表を分けてつなぐデータベースを、**リレーショナルデータベース(RDB)**と呼びます。


---

### 4. SQLとは（データベースへの命令）

Excelでは、マウスで表をクリックして直接入力します。
データベースでは、**SQL** という言葉で「こうしてほしい」と**命令**を書き、DBMSに実行してもらいます。

SQLは、MySQL・PostgreSQL・SQLite など、ほとんどのRDBで共通して使える言葉です。
まずは、次の4つの命令を覚えましょう。

| 命令 | 意味 | Excelでいうと |
| --- | --- | --- |
| `SELECT` | データを**取り出して見る** | 表を見る・フィルタで絞り込む |
| `INSERT` | データを**追加する** | 新しい行を書き足す |
| `UPDATE` | データを**書き換える** | セルの値を書き直す |
| `DELETE` | データを**削除する** | 行を削除する |

SQLは、英語の文のように読むことができます。

```sql
SELECT student_name FROM students WHERE class_id = 1;
```

| 部分 | 意味 |
| --- | --- |
| `SELECT student_name` | 学生の名前を取り出して |
| `FROM students` | students（学生）の表から |
| `WHERE class_id = 1` | ただし、class_id が 1 の学生だけ |

→「class_id が 1 の学生の名前を見せて」という命令になります。

- 文の最後には `;`（セミコロン）を付ける
- `--` から後ろはコメント（メモ）で、実行されない

この後に出てくるSQLは、今は**何をしているかの雰囲気がわかれば大丈夫**です。書き方はこの後の授業でくわしく学びます。

### 5. データベースだと何が便利か

#### ① 1か所直すだけで、全部に反映される

担任を佐藤先生から森先生に変えるときは、classes の1行を直すだけです。
ITエンジニア学科の学生20人分は、何も書き換えなくても担任が「森隆」になります。

```sql
UPDATE classes SET teacher_id = 8 WHERE class_id = 1;
```

→「classes の表で、class_id が 1 のクラスの teacher_id を 8 に書き換えて」という命令です。

#### ② 間違ったデータを入れさせない

表を作るときにルール（**制約**）を決めておくと、データベースが自動でチェックしてくれます。

```sql
-- 学籍番号 261001 はすでにいるので、エラーになる
INSERT INTO students VALUES (261001, '新入生', 'しんにゅうせい', '2007-05-01', 1);
-- → UNIQUE constraint failed: students.student_id

-- class_id = 99 のクラスは存在しないので、エラーになる
INSERT INTO students VALUES (261021, '新入生', 'しんにゅうせい', '2007-05-01', 99);
-- → FOREIGN KEY constraint failed
```

→ どちらも「students の表に、この学生を追加して」という命令ですが、ルールに合わないのでデータベースが断ってくれます。

学科名や担任名を学生ごとに手で書かないので、表記ゆれも起きません。

#### ③ 見たい形で、いつでも一覧を作れる

表を分けても、SQLでつなげて（JOIN）表示すれば、Excelの名簿と同じ形の一覧がいつでも作れます。

```sql
SELECT s.student_id, s.student_name, c.enrollment_year, c.department_name, t.teacher_name
FROM students AS s
JOIN classes  AS c ON s.class_id   = c.class_id
JOIN teachers AS t ON c.teacher_id = t.teacher_id;
```

→「学生・クラス・先生の3つの表を、番号が同じもの同士でつなげて、学籍番号・氏名・入学年度・学科・担任を見せて」という命令です。

| student_id | student_name | enrollment_year | department_name | teacher_name |
| --- | --- | --- | --- | --- |
| 261001 | 青木翔 | 2026 | ITエンジニア学科 | 佐藤太郎 |
| 261002 | 石川葵 | 2026 | ITエンジニア学科 | 佐藤太郎 |
| … | … | … | … | … |

#### ④ 集計や検索がかんたん

「学科ごとの学生数」も、SQL1つで出せます。学生がまだいない学科も0人として表示できます。

```sql
SELECT c.department_name, COUNT(s.student_id) AS 学生数
FROM classes AS c
LEFT JOIN students AS s ON c.class_id = s.class_id
GROUP BY c.class_id, c.department_name;
```

→「クラスと学生をつなげて、学科ごとに学生の人数を数えて」という命令です。

| department_name | 学生数 |
| --- | --- |
| ITエンジニア学科 | 20 |
| ITキャリア養成科 | 0 |
| 映像クリエイター学科 | 0 |
| … | … |

「担任を持っていない先生」のような、Excelの名簿では見つけられない情報も探せます。

```sql
SELECT t.teacher_name
FROM teachers AS t
LEFT JOIN classes AS c ON t.teacher_id = c.teacher_id
WHERE c.class_id IS NULL;
-- → 森隆、岡田恵
```

→「先生とクラスをつなげて、つながるクラスがない（担任を持っていない）先生の名前を見せて」という命令です。

#### ⑤ たくさんの人が同時に使える

Excelのファイルは、同時に編集するとデータがぶつかったり、「最新版はどのファイル？」となったりしがちです。
データベースは、複数の先生が同時に成績を入力しても、データが壊れないように管理してくれます。

---

### 6. まとめ

| | Excelの一覧 | データベース |
| --- | --- | --- |
| 同じ情報 | 何度も書く | 1か所にだけ書く |
| 修正 | 全部の行を直す（直し忘れが起きる） | 1か所直せば全部に反映 |
| 入力ミス | そのまま入ってしまう | 制約でエラーにしてくれる |
| 一覧・集計 | 手作業やフィルタで作る | SQLで見たい形にすぐ出せる |
| 同時利用 | ぶつかりやすい | 複数人で安全に使える |

- データベースでは、**「何についての情報か」ごとに表を分けて、番号でつなぐ**
- そうすることで、**データを正しく保ちながら、必要な形でいつでも取り出せる**
