### 第1正規形

**1つのセルに、複数の値を入れない。**

例えば、

| 学生ID | 学生名 | 科目       |
| ---- | --- | -------- |
| 1    | 田中  | 数学、英語、国語 |

これは「科目」に複数の値が入っています。

↓

| 学生ID | 学生名 | 科目 |
| ---- | --- | -- |
| 1    | 田中  | 数学 |
| 1    | 田中  | 英語 |
| 1    | 田中  | 国語 |

**1つのセルには1つの値**にします。

---

### 第2正規形（2NF）

**主キーの一部だけに依存するデータを分離する。**

例えば、

| 学生ID | 科目ID | 学生名 | 科目名 | 点数 |
| ---- | ---- | --- | --- | -- |
| 1    | 101  | 田中  | 数学  | 80 |
| 1    | 102  | 田中  | 英語  | 70 |
| 2    | 101  | 佐藤  | 数学  | 90 |

主キーが「学生ID＋科目ID」だとすると、

* 学生名 → 学生IDだけで決まる
* 科目名 → 科目IDだけで決まる
* 点数 → 学生ID＋科目IDで決まる

となっています。

そこで、

**学生**

| 学生ID | 学生名 |
| ---- | --- |
| 1    | 田中  |
| 2    | 佐藤  |

**科目**

| 科目ID | 科目名 |
| ---- | --- |
| 101  | 数学  |
| 102  | 英語  |

**成績**

| 学生ID | 科目ID | 点数 |
| ---- | ---- | -- |
| 1    | 101  | 80 |
| 1    | 102  | 70 |
| 2    | 101  | 90 |

のように分けます。

---

### 第3正規形（3NF）

**主キーではない項目に依存するデータを分離する。**

例えば、

| 学生ID | 学生名 | クラスID | クラス名 |
| ---- | --- | ----- | ---- |
| 1    | 田中  | 10    | 1年A組 |
| 2    | 佐藤  | 10    | 1年A組 |

この場合、

```text
学生ID → クラスID → クラス名
```

となっています。

「クラス名」は学生IDではなく、**クラスIDによって決まる**ので、クラス情報を別テーブルにします。

**学生**

| 学生ID | 学生名 | クラスID |
| ---- | --- | ----- |
| 1    | 田中  | 10    |
| 2    | 佐藤  | 10    |

**クラス**

| クラスID | クラス名 |
| ----- | ---- |
| 10    | 1年A組 |

---

### 3つを一言で覚えるなら

| 正規形       | 簡単に言うと            |
| --------- | ----------------- |
| **第1正規形** | 1つのセルに1つの値        |
| **第2正規形** | 主キーの一部に依存するデータを分離 |
| **第3正規形** | 主キー以外に依存するデータを分離  |

今回作っていた

```text
classes
students
subjects
scores
```

というテーブル構成も、まさに**正規化の考え方を使った設計**になっています。


> **正規化 = データの重複や矛盾を減らすために、テーブルを適切に分割すること**
