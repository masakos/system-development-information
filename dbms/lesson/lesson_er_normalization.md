## 全体の流れ（約80〜90分）

**軸：先に「完成した5つのテーブル」でリレーションを描き、そのあとに「なぜ5つに分けたのか」を正規化で答えていく。**
正規化の最後に、学生が自分で描いたER図にたどり着く。

## ① 導入（5分）

- 「学生管理システムのデータベース」という設定を伝える
- 5つのテーブル名と役割だけを紹介する（教員・クラス・学生・科目・成績）

## ② 作業：リレーションを描く（15分）

- ワークシートの1ページ目を配る（PKだけ印があり、FKの印はない）
- **CREATE文はまだ見せない**
- ヒントは1つだけ：「**同じ名前の列が、別のテーブルにも出てくるところを探そう**」
- 早く終わった学生には、線の両端の多重度（`1`、`0..*` など）にも挑戦させる

## ③ 答え合わせ：CREATE文を見る（10〜15分）

CREATE文で注目させるのは3つだけ。`CHECK` は「入力チェック」とだけ言って流す。

| CREATE文 | ER図でわかること |
| --- | --- |
| `PRIMARY KEY` | PK |
| `FOREIGN KEY ... REFERENCES` | 線が引ける場所。外部キーを持つ側が「多」 |
| `NOT NULL`（外部キーの列） | 「1」側が `1`（必ず1つ。`0..1` ではない） |

- `FOREIGN KEY` を数えさせる → 5つ → **線も5本**
- **`scores` に外部キーが2つ** → 多対多と中間テーブルの話（ワークシート問い3）
- 「多」側が「0以上（`0..*`）」になる理由は、実データで確認する（05 第1部 2）
  - 担任を持たない先生（森・岡田）、学生のいないクラス、未受験の成績（坂本さん）
- 余裕があれば `classes` の `UNIQUE (enrollment_year, teacher_id)` を見せて、
  「同じ年度は1人1クラスなのに、なぜ1対1ではないのか？」を考えさせる（年度が違えば複数担任できる）

## ④ 橋渡し：「1枚の表ではダメなの？」（5分）

- 05 第2部 1 の JOIN の SQL を DB Browser で実行して見せる → 99行の1枚の表
- 「Excelならこの1枚で管理しそうだよね。わざわざ5つに分けたのはなぜ？」と問いかける

## ⑤ 困ることを探す（10分）

- 99行の表を見ながら「この表で困ることを探して」と投げかける
- 出た意見を、更新・挿入・削除の3つの異常に整理する

| 異常 | 学生から引き出したい例 |
| --- | --- |
| 更新 | 森先生の名前が40行にある。全部直さないと矛盾する |
| 挿入 | 学生のいないクラス（ITキャリア養成科）を登録できない |
| 削除 | ビジネスマナーの成績を消すと、岡田先生の情報も消える |

- 「この問題をなくすために表を分けていく手順＝正規化」と定義する

## ⑥ 正規化（20〜30分）

各段階で「**この列は、何が決まれば決まる？**」と問いかけるのがポイント。
先に「関数従属（A が決まれば B が決まる）」を、例で軽く押さえておく。

| 段階 | 問いかけ | 結果 |
| --- | --- | --- |
| 非正規形 → 第1正規形 | 「Excelだと、1つのセルに科目を複数書いちゃわない？」 | 1科目＝1行に展開する → ④の99行の表が第1正規形 |
| 第1正規形 → 第2正規形 | 「氏名は、学籍番号だけで決まる？　単位数は？」 | 学生・科目・成績に分かれる |
| 第2正規形 → 第3正規形 | 「担任名は、本当は何で決まっている？」 | 教員とクラスが分かれる |

- 第1正規形は「並べ直しただけ」に見えるので **軽めに**。時間は第2・第3正規形に使う
- 第3正規形まで来たら、**②で描いたER図と同じ形になる** ことを確認する
- ⑤の異常が、それぞれどの段階で解決したかを振り返る（05 第2部 6「第3正規形で解決したこと」）

## ⑦ まとめ（5分）

- 保存するときは分けて重複をなくし、見るときは JOIN でくっつける
- 外部キー（分けた表をつなぐために残した列）＝ ER図の線
- 覚え方：「すべての列は、キーに、キー全体に、キー以外の何物でもなく従属する」
